## 1. 技術選擇

- **純靜態網頁**：HTML + CSS + 原生 JavaScript，沒有框架、沒有建置步驟，可以直接部署到 GitHub Pages。
- **存檔**：`localStorage`，有兩個 key：
  - `mine_config_v1`：編輯模式的設定覆蓋
  - `mine_save_v1`：玩家存檔
- **字型**：俐方體11號（jsDelivr gh CDN）→ DotGothic16（Google Fonts）→ 系統等寬字，依序退回。
- **機率引擎和畫面完全分離**：`engine.js` 沒有 DOM 依賴，可以在 Node 裡直接 `require` 來跑模擬。

## 2. 檔案結構

```
index.html          畫面骨架（所有可編輯元素都有 data-edit 屬性）
css/style.css       像素風樣式、編輯模式樣式
js/config.js        DEFAULT_CONFIG：所有數值、文字、顏色（唯一的資料來源）
js/engine.js        MineEngine：swing()（揮一次）、simulate()（模擬）
js/game.js          Game：存檔、畫面渲染、玩家操作
js/editor.js        Editor：版面拖曳、表單、模擬器、匯出匯入
docs/               脈絡文件
```

設定的載入順序：`deepMerge(DEFAULT_CONFIG, localStorage[mine_config_v1])`。合併時陣列整個覆蓋，物件逐鍵合併。

## 3. 狀態機（engine.js `swing`）

每座礦坑各自有一份 `playState`：

```js
{ state: "normal"|"koukaku"|"zencho"|"vein", zenchoLeft, fakeLeft, veinLeft, sinceHit, chain }
```

`s` 代表設定編號減 1，範圍 0～5。

### 3.1 state = vein（礦脈中）
1. 從 `rules.veinTable` 抽小役（依序累加 legend→common 的機率，剩下的是 rubble）。
2. 以 `toolDrop.vein` 的機率掉落工具。
3. `veinLeft--`；歸零時，以 `vein.continue[s]` 的機率重置為 `vein.length` 並讓 `chain++`，否則回到 `normal`，同時 `sinceHit = 0`。
4. 不抽期待度（`omen = -1`）。

### 3.2 state = zencho（前兆中，已確定當選）
1. 從 `rules.itemTable` 抽小役，並抽工具掉落。
2. `zenchoLeft--`；歸零時進入 `vein`，`veinLeft = length`，`chain = 1`。
3. 期待度從 `omen.zencho` 抽。

### 3.3 state = normal / koukaku
1. 從 `itemTable` 抽小役，並抽工具掉落。
2. `sinceHit++`。
3. 以 `veinWin[normal|koukaku][小役][s]` 的機率判定當選。
4. 沒當選且 `sinceHit >= tenjou` 時，強制當選（天井）。
5. 當選時：進入 `zencho`，`zenchoLeft = randInt(zencho.min, zencho.max)`，並清除假前兆。
6. 沒當選時：
   - normal：以 `toKoukaku[小役][s]` 的機率移行到 koukaku
   - koukaku：以 `koukakuDrop` 的機率轉落回 normal
7. 期待度（沒當選時）：
   - 如果假前兆進行中：`fakeLeft--`，從 `omen.fake` 抽
   - 否則以 `fakeZencho[normal|koukaku]` 的機率開始假前兆，長度 `randInt(min, max)`，並從 `omen.fake` 抽
   - 否則依目前狀態，從 `omen.normal` 或 `omen.koukaku` 抽

> 注意：`sinceHit` 在前兆期間不會增加，礦脈結束後才歸零。畫面上的「累計」就是這個值。

## 4. 經濟模型

- 工具每揮成本 = `price ÷ durability`。5 階分別為 2 / 6 / 16 / 40 / 100。
- 礦石售價 = `category.value × mine.mult × (1 + 所有工具鍛造等級加總 × upgrade.valuePerLv)`。
- 礦坑倍率 `mult` = 1 / 3 / 8 / 20 / 50，和工具每揮成本同比例，所以同階工具挖同階礦坑時，機械割大致一樣。
- 工具等級必須 ≥ 礦坑等級才能使用。自動裝備會選「可用的工具中階級最低、耐久最少」的一把。
- 工具掉落：
  - 以 `sameTier` 的機率掉落同階工具，否則平均分配到較低階（第 1 層只會掉木鎬）
  - 剩餘耐久比例是 `minDur`～`maxDur` 之間的隨機值
- 模擬器的機械割 = (礦石價值 + 工具掉落期望價值) ÷ (揮數 × 同階每揮成本)。**不含鍛造加成和廣告收入**。

## 6. 已知限制與待確認（請 AI 特別檢查）

1. **期待度統計的定義**：「真的在前兆中」只計算 omenKey === zencho 的揮數，當選的那一揮本身也算在內。這樣定義是否合理？
2. **天井計數**包含高確期間，不包含前兆與礦脈期間。
3. **設定的決定方式**：使用 `日期字串 + 礦坑id` 的雜湊，所以玩家改手機日期就能換設定。這在單機版可以接受，雲端版必須改由伺服器決定。
4. **防作弊**：所有邏輯都在前端，`localStorage` 可以被竄改。雲端版需要伺服器驗證，或至少把抽選移到伺服器。
5. **編輯模式對所有人開放**（左上角的 ✎）。正式上線前應該隱藏，或用網址參數 `?edit=1` 開啟。
6. **圖片存成 dataURL** 放在 `localStorage`，約 5MB 上限；存不下時會提示失敗。正式版應改用實體檔案。
7. **`itemIndex()` 每次查價都重建**，數量少所以沒有效能問題，但可以改成快取。
8. **鍛造升級時**，會把已持有同型工具的最大耐久和目前耐久一起加上差值。
9. 自動模式的停止條件：期待度 ≥ `play.autoStopOmen`（預設紫）、礦脈開始或結束、天井、挖到傳說、最後一把工具壞掉。
10. 切到其他分頁或 App 進入背景時，會停止自動模式並立即存檔。

## 7. 請 AI 驗證的問題清單

- [ ] `swing()` 的狀態轉移有沒有漏掉的情況（例如假前兆期間當選、高確轉落與移行同時發生）？
- [ ] `pickCategory` 在機率加總 > 1 時的行為（目前會讓 rubble 永遠抽不到，而且後面的類別也會被截斷）。是否需要加上防呆？
- [ ] 機械割的計算方式，是否能反映玩家實際的損益？
- [ ] 設定差是否足以讓玩家「推測」設定，但又不會太容易被看穿？
- [ ] `deepMerge` 在預設設定新增欄位、而舊的覆蓋檔沒有該欄位時，是否能正確補上？
- [ ] 手機 Safari 和 Chrome 上的觸控拖曳、`100dvh`、safe-area 是否正常？
- [ ] 有沒有 XSS 風險？玩家名稱是用 textContent 放進 HUD，但編輯模式的文字欄位是透過 innerHTML 輸出。
