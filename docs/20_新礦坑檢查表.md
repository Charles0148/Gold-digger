# 新礦坑檢查表（2026-10-05，紅晶系統一起定案）

> 以後每新增一座礦坑，都要照這份檢查表做。擁有者說過，之後的礦坑可能很特別，例如故事向，所以分類要先想清楚。
> 原則：**沒寫的設定一律當作「不適用」**。這樣不會壞掉，也不會用猜的。

## 一、先選類型（白話）

一座礦坑可以同時有好幾種性質，例如「故事型＋探索型＋限時活動」。先選一個主要類型，再勾選它有哪些能力。

| 類型 | 白話說明 | 例子 | 紅晶相關預設 |
|---|---|---|---|
| 標準機台型 | 揮一下抽一次；有通常、高確、礦脈 | m1～m5 | 每一項都可以開啟 |
| 角色機台型 | 有好感、對話、帶路、關卡和獎勵段 | m6 三位前輩的考驗 | 要逐一標明每個階段是否付費、是否免費 |
| 故事劇情型 | 主要看故事、選選項、過章節 | 未來 | 挖礦進度條、探測器、鑽頭不扣耐久，預設都關閉 |
| 探索收集型 | 走地圖、搜地點、收集東西 | 未來 | 依「完成一次探索」給進度 |
| 限時活動型 | 有開始和結束日期，有活動專屬存檔和獎勵 | 未來 | 所有紅晶來源預設關閉，要逐項核准 |
| 展示型（不耗耐久） | 純對話、圖鑑、展示或社交 | 未來 | 不產紅晶，不能用探測器和鑽頭 |

## 二、每座礦坑都要回答的問題

1. **玩家在這裡反覆做什麼？** 用一句話寫出來。
2. **會扣工具耐久嗎？** 哪些動作扣、哪些不扣（例如對話、選擇、演出都不扣）。
3. **有哪些狀態？** 每個狀態都要標明：扣不扣耐久、是不是免費的、離開礦坑時要不要清除。
4. **紅晶要怎麼處理？**
   - 挖礦進度條：要不要累積？每扣 1 耐久或每完成一次動作，累積多少？
   - 礦脈探測器：能不能用？什麼算「機會」？機率提高幾倍？哪些狀態暫停計數？
   - 紅岩鑽頭：哪些狀態不扣耐久？每把最多免扣幾次？
   - 地底凍結：有沒有凍結？凍結要不要給紅晶？
5. **有觀測鏡嗎？** 用哪一份機率表？
6. **要不要加進委託板、圖鑑、成就？**
7. **存檔怎麼存？** 永久保存，還是每天、每輪、活動結束時清除？
8. **故事型另外要回答：** 章節、選項和獎勵怎麼記錄，才不會重看一次就重領一次獎勵？

## 三、工程欄位（給 AI 用）

```js
mine.kind = "standard";   // standard／character／story／explore／event／display

mine.capabilities = {
  usesDurability: false, hasChanceCards: false, hasRewardRun: false, hasFreeze: false,
  hasGlass: false, hasBoardItems: false, hasDex: false, hasAchievements: false
};

mine.ruby = {
  progress:  { enabled: false, mode: "disabled", unitsPerDurability: 0, unitsPerAction: 0, eligibleTags: [] },
             // mode：durability（扣耐久）／action（完成一次探索動作）／chapter（完成章節）／event
  probe:     { enabled: false, multiplier: 0, count: 10, eligibleTags: [], opportunityTags: [], pauseTags: [] },
  drillFree: { enabled: false, phaseTags: [], maxFreePerTool: 0 },
  freezeReward: { enabled: false, eventTag: null }
};

mine.glass = { enabled: false, tableId: null };
mine.content = { boardItems: false, dex: false, achievements: false };
mine.savePolicy = { scope: "persistent", resetOnLeave: false, resetOnDay: false, eventEnd: null };
             // scope：persistent（永久）／daily（每天）／run（每輪）／event（活動）
```

**引擎統一回報：** 每一揮或每一次動作，引擎都要回報下面四項。紅晶系統只看這四項，不需要了解每台機器的內部規則。

| 欄位 | 意思 |
|---|---|
| `spentDurability` | 這次扣了多少耐久 |
| `phaseTag` | 現在是什麼狀態 |
| `opportunityTag` | 有沒有出機會牌，出的是哪一種 |
| `rewardEventId` | 領獎的編號，用來防止重複領取 |

## 四、沒寫時的安全預設

- 不產挖礦紅晶。
- 探測器按鈕不能按，也不會消耗道具。
- 紅岩鑽頭照常扣耐久。
- 不給凍結紅晶。
- 沒有觀測鏡。
- 不加進委託板、圖鑑或成就。
- 離開礦坑時保留資料，不自動刪除。
- 不認得的狀態，當成一般付費揮擊，但不套用任何紅晶特殊效果。

### 實作位置（2026-10-05 第 1～3 批）

- 每座礦坑的紅晶設定實際放在 `js/config.js` 的 `ruby.mines[礦坑id]`（`kind`、`progress.perDur`、`probe.mult`、`drillFree.phases／maxPerTool`、`freezeReward`），不是放在 `mines` 陣列裡：編輯器存的設定檔會整個蓋掉 `mines` 陣列，新欄位會不見。沒列出的礦坑＝全部不適用（第四節）。
- 引擎回報：`spentDurability` 由 game.js 的 `drillSpend` 回傳（鑽頭免扣＝0）；`phaseTag` 用 `stateBefore`（m1～m5：`bonus`＝礦脈；m6：`bonus`＝前輩的心意）；`opportunityTag` 用引擎回傳的 `res.probe`（這一揮有沒有吃到探測器）；`rewardEventId` 目前只有鑽頭小結晶用工具編號（`save.ruby.drops`）防重複。
- 純邏輯 `js/ruby.js`、測試 `node tools/ruby-test.js`、模擬 `node tools/sim.js` 的 §8.9。

## 六、新增一座礦坑的步驟

1. 用一句話寫清楚玩家在這座礦坑反覆做什麼。
2. 選主要類型，勾選它有哪些能力。
3. 列出所有狀態，標明是否扣耐久、是否免費、離開礦坑時是否清除。
4. 讓引擎回報四項統一資料：`spentDurability`、`phaseTag`、`opportunityTag`、`rewardEventId`。
5. 填寫紅晶、探測器、鑽頭、凍結、觀測鏡的設定；不適用的也要明寫 `enabled:false`。
6. 決定要不要加進委託板、圖鑑、成就和每日功能。
7. 舊存檔缺少欄位時自動補預設值；頂層 `save.v` 維持 1。
8. 測試：正常玩、掛機、換礦坑、重新整理、斷線、跨日、重複領獎。
9. 用模擬器算：機械割、每天的紅晶量、探測器效果、鑽頭的實際壽命。
10. 擁有者實際玩過、確認沒問題，才標成 `VERIFIED`。
