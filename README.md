# 深層礦脈（挖礦遊戲）

以日本 SLOT（パチスロ）隨機性為基礎的手機直式文字挖礦遊戲。
純靜態網頁：HTML + CSS + 原生 JavaScript，沒有框架、沒有建置步驟。

- **線上版**：GitHub Pages（`main` 分支一推上去就生效）
- **目前版本**：見 `js/version.js`，遊戲畫面右下角也會顯示
- **專案擁有者**：沒有程式背景，由 AI 實作。**請用繁體中文溝通。**

### 工作原則（專案擁有者定的，請遵守）

1. **不要假裝知道。** 文件互相矛盾、程式和文件不同、找不到實作 → 直接說「這裡無法確認」，並列出文件怎麼寫、程式怎麼做、你建議怎麼處理。**禁止自己選一個看起來合理的答案默默做下去。**
2. **數值以 `js/config.js` 為準。** 文件裡的數字是說明用途，對不上時以 config 為準。
3. **功能狀態要分清楚**：`IDEA → PROPOSED → ACCEPTED → IMPLEMENTED → VERIFIED`。
   「程式寫完了」只到 IMPLEMENTED；**只有專案擁有者實際操作確認過才是 VERIFIED**。
4. **問題分三類**：BUG（沒按已確認規格運作，可直接修）／SPEC CONFLICT（文件打架，要先問）／DESIGN RISK（程式沒錯但你覺得不好玩，先報告不要自己改）。
5. **遊戲設計決策必須先講。** 工程安全問題可以直接修；但覺得機械割太高、恩惠太強、某台太爽——**先說，不要擅自調低**。
6. **只有擁有者說「上傳」才推 GitHub。** 平常改完寫回他的資料夾即可。

## 檔案結構

```
index.html          入口，載入下面所有 js
css/style.css       樣式
js/version.js       版本號（每次上傳前更新，index.html 的 ?v= 要一起改）
js/config.js        ★ 所有遊戲數值（DEFAULT_CONFIG）
js/engine.js        第一台機台引擎（m1～m5，AT／連續演出／共鳴／上位）
js/engine2.js       第二台機台引擎（m6，約會→ST→一轉定勝負→BONUS）
js/game.js          UI 與遊戲流程（兩台共用）
js/editor.js        編輯模式（玩家版不會載入，見下）
js/cloud.js         雲端存檔、帳號、信箱（Supabase REST，沒有外部函式庫）
js/cloud-config.js  Supabase 連線資料（公開值，不是密碼）
docs/               文件
```

**localStorage 的三個 key**：`mine_config_v4`（編輯模式的設定覆蓋）、`mine_save_v1`（玩家存檔）、`mine_cloud_v1`（登入 session）。

## 在自己電腦上跑

直接用 Chrome 打開 `index.html` 就能玩，不需要伺服器。

## 編輯模式

**玩家版根本不會下載 `editor.js`。** 要叫出 ✎ 需要兩個條件同時成立：

1. 網址帶 `?dev=1`
2. 而且 —— **本機開檔案**（`file://` 或 localhost，一律放行），**或** 已登入的帳號在 Supabase 的 `admins` 名單裡

| 情況 | ✎ |
|---|---|
| 自己電腦 `index.html?dev=1` | 出現 |
| 線上網址 `?dev=1` + 管理員帳號已登入 | 出現 |
| 線上網址 `?dev=1` 但不是管理員 | **不出現**，`editor.js` 也不會被下載 |
| 沒加 `?dev=1` | 不出現 |

### 改數值的流程

1. `?dev=1` 進編輯模式
2. 在「版面／顏色／圖片／文字／數值／前輩台」分頁調整（改動立即套用，存在這台裝置）
3. 「模擬」分頁確認機率沒跑掉
4. 「存檔/測試」→ **下載設定檔**，把 `mine-config.json` 放進這個資料夾
5. 跟 Claude 說「套用設定檔」→ 寫回 `js/config.js`

### 測試工具的旗標

「顯示設定／顯示抽選數字／強制設定」這三個開關**只在開發者模式底下生效**。
設定值會存在存檔裡（也會同步到雲端），但正常玩的網址一律當作它們是關的——
所以忘記關也不會汙染正式遊玩的數據。

## 雲端（Supabase）

帳號、跨裝置存檔、信箱都接在 Supabase 上，**免費方案**。

- 設定步驟與後台怎麼看：`docs/05_雲端存檔設定.md`
- 信箱發獎勵、管理員權限：`docs/06_信箱與開發者權限.md`

沒有網路或 `js/cloud-config.js` 留空時，遊戲**照常單機可玩**。

⚠️ **免費專案閒置一週會被暫停**，遊戲會顯示「同步失敗」。到 Supabase Dashboard 按 **Restore** 就會醒（資料不會不見）。

### 誠實說明：雲端不等於防作弊

遊戲的抽選邏輯全部在瀏覽器裡跑。玩家改完數字再上傳，伺服器照收。
目前的雲端只解決「換手機接得回來」和「兩台裝置不要互相覆蓋」。
真正的防作弊要把引擎搬到伺服器端，那是還沒做的事。

## 上傳到 GitHub

`main` 分支就是線上版，推上去 1～2 分鐘後生效。

**上傳後務必逐檔比對線上版**，確認沒有漏檔——曾經發生過線上版落後 5 個版本、朋友試玩回報的其實是舊版行為。

每次上傳前：

1. 更新 `js/version.js` 的版本號
2. `index.html` 裡所有的 `?v=` 一起改成同一個版本（這是手機快取更新的機制）
